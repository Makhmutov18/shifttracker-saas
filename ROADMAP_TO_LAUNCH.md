# ROADMAP TO LAUNCH

План запуска `Порядок.Смены` с фокусом на живой пилот, быструю обратную связь и первые продажи. Это не обещание идеального продукта, а рабочая дорожная карта: сначала MVP, потом пилот, затем упаковка и коммерческий запуск.

## 1. Цель продукта

`Порядок.Смены` помогает кофейням и малому общепиту:

- фиксировать смены без Excel и лишней ручной рутины;
- быстро согласовывать и утверждать смены;
- видеть выплаты прозрачно и без споров;
- хранить историю смен, корректировок и точек;
- дать админам и владельцам спокойный рабочий инструмент вместо хаоса в чатах.

Главная цель до запуска — доказать, что продукт реально используют в одной живой кофейне и за него готовы платить.

## 2. P0 до MVP freeze

Дедлайн: `31 июля 2026`

Что должно быть стабильно до freeze:

- создание смены сотрудником;
- approve / reject смен;
- история и выплаты после approve;
- payroll считает только approved смены;
- fixed shift и hourly не ломают расчёт;
- фильтр по точкам работает;
- архив сотрудников не ломает историю;
- обычный сотрудник не видит управление;
- permissions не ломаются;
- Telegram auth работает;
- app не показывает blank screen;
- ErrorBoundary покрывает runtime crash;
- UI не содержит mojibake;
- light / dark theme читаемы.

Что желательно, но не блокирует freeze:

- XLSX export;
- web admin polish;
- onboarding checklist;
- additional UI cleanup.

## 3. Пилот на кофейне

Дедлайн: `10 августа 2026`

Цель пилота:

- поставить продукт на живой объект;
- проверить, что сотрудники реально создают смены;
- проверить approve flow у владельца или админа;
- собрать обратную связь от команды;
- понять, где пользователи спотыкаются;
- подтвердить, что основные выплаты видны в UI.

Что считаем успехом пилота:

- хотя бы одна кофейня ведёт смены через продукт;
- владелец или админ регулярно открывает History / payroll;
- нет критичных падений приложения;
- ручная работа сократилась;
- есть понятный запрос на оплату или продолжение.

## 4. Web Admin roadmap

Дедлайн для первого полноценного слоя: после пилота, но не позже `31 августа 2026` как часть упаковки.

Позиция:

- web admin полезен;
- web admin не блокирует пилот;
- если основные выплаты и история видны в Mini App, пилот можно запускать без идеального desktop admin.

Что идти в roadmap:

- удобный просмотр сотрудников;
- точки и архивы;
- история действий;
- payroll summary;
- экспорт;
- edit flows без лишней сложности.

## 5. AI / DeepSeek roadmap

Дедлайн: после пилота, отдельным этапом, не блокирует запуск.

Позиция:

- AI не должен блокировать пилот;
- сначала нужна надёжная рабочая база;
- только потом — подсказки, авторазбор и отчёты.

Что можно отложить:

- AI-аналитика смен;
- авто-рекомендации по payroll;
- подсказки по management decisions;
- DeepSeek-generated summaries.

## 6. Платежи и тарифы

Дедлайн: `31 августа 2026` для упаковки, `15 сентября 2026` для первого коммерческого запуска.

Позиция:

- автоматические платежи не блокируют первые ручные продажи;
- первые продажи можно делать вручную;
- важно быстрее получить первые деньги и подтверждение спроса;
- биллинг должен быть понятным, но не обязан быть идеальным на пилоте.

Что нужно к коммерческому запуску:

- понятный тариф;
- понятный onboarding;
- понятные условия пилота и платного перехода;
- базовый процесс оплаты;
- аккуратные ограничения по количеству точек или сотрудникам, если это нужно бизнесу.

## 7. Маркетинг и упаковка

Дедлайн: `31 августа 2026`

Нужно собрать:

- короткое позиционирование продукта;
- один главный оффер;
- короткое объяснение пользы для кофейни;
- понятный список фич для пилота;
- короткий FAQ;
- скриншоты или видео демо;
- простую презентацию для первых переговоров.

Важно:

- не обещать идеальный продукт;
- не обещать все будущие модули сразу;
- не перегружать лендинг и материалы сложной терминологией;
- показывать пользу: смены, выплаты, контроль, прозрачность.

## 8. Promo materials

Что нужно подготовить:

- one-pager для переговоров;
- короткий PDF с оффером;
- 3-5 скриншотов ключевых экранов;
- короткое demo video;
- список частых вопросов и ответов;
- шаблон сообщения для первого контакта с кофейней;
- короткий текст для Telegram / WhatsApp / личных встреч.

Главный принцип:

- материалы должны продавать понятную пользу;
- материалы не должны обещать то, чего ещё нет в продукте.

## 9. Launch checklist

К `15 сентября 2026` должны быть готовы:

- один стабильный пилот;
- понятная история успеха пилота;
- рабочая воронка первых продаж;
- тарифы и базовая упаковка;
- понятные материалы для продаж;
- понятный список того, что включено в MVP;
- подтверждение, что app не ломается в обычном сценарии использования.

## 10. Что НЕ делаем до пилота

- не делаем идеальный продукт;
- не делаем глубокий AI-слой;
- не делаем сложный web admin раньше времени;
- не делаем автоматические платежи как блокирующую зависимость;
- не обещаем все будущие модули сразу;
- не расползаемся в лишние фичи;
- не возвращаем onboarding checklist как обязательную фичу;
- не тратим время на polish, который не помогает пилоту;
- не блокируем запуск из-за XLSX export, если основные выплаты уже видны в UI.

## Дедлайны

- `31 июля 2026` — MVP freeze
- `10 августа 2026` — пилот на живой кофейне
- `31 августа 2026` — упаковка и материалы для продаж
- `15 сентября 2026` — первый коммерческий запуск
