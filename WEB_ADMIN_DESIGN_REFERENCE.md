# WEB ADMIN DESIGN REFERENCE

Этот документ фиксирует визуальный ориентир для будущей web-admin админки `Порядок.Смены`. Это не код, не макет для прямого копирования и не готовый интерфейс. Здесь зафиксировано направление, которое можно использовать позже как основу для desktop/tablet admin.

## 1. Назначение web-admin

Web-admin нужен как отдельный интерфейс для владельца и управляющего, когда удобнее работать с ноутбука или планшета.

Telegram Mini App остаётся основным рабочим экраном для сотрудников и быстрых действий.

Web-admin нужен для:

- сотрудников и команд;
- точек и архивов;
- выплат и сводок;
- истории действий;
- экспорта;
- настроек;
- более спокойной работы на большом экране.

## 2. Что берём из Claude concept

Из концепта берём не HTML, а идею и структуру:

- левый sidebar;
- workspace selector;
- topbar с фильтрами `Все точки` и месяц;
- KPI row:
  - `К выплате за месяц`;
  - `Смен ждёт подтверждения`;
  - `Активные сотрудники`;
  - `Точек`;
- блок `Требует внимания`;
- таблица `Последние смены`;
- `Сводка выплат по точкам`;
- спокойная светлая B2B-стилистика;
- синий accent для `Порядок.Смены`.

## 3. Что НЕ переносим напрямую

- static HTML;
- Google Fonts;
- hardcoded colors;
- fake data;
- inline SVG as-is;
- min-width без responsive;
- прямое копирование CSS;
- новую UI-библиотеку без отдельного решения.

## 4. Будущие страницы web-admin

- Обзор;
- Смены;
- Сотрудники;
- Точки;
- Выплаты;
- Экспорт;
- Настройки;
- позже AI-отчёты.

## 5. Правила будущей реализации

- стек React / Vite;
- использовать существующий backend / API;
- не дублировать бизнес-логику;
- соблюдать permissions;
- использовать CSS variables и theme tokens;
- обязательные loading / error / empty states;
- русский UI;
- no mojibake;
- light / dark compatibility, если web-admin будет поддерживать темы.

## 6. Приоритет

Web-admin не блокирует пилот.

Сначала должен оставаться стабильным Telegram Mini App. Web-admin MVP логично делать после пилота или после MVP freeze.
