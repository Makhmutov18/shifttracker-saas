# SMOKE TESTS

Короткий ручной чеклист для быстрой проверки `shifttracker-saas` после изменений.

## 1. Создание смены сотрудником

### Сценарий
1. Открыть приложение как обычный сотрудник.
2. Создать новую смену.

### Ожидаемый результат
- Смена сохраняется без ошибки.
- Смена появляется в истории.
- Статус понятен и не выглядит как blank screen.

## 2. Approve / Reject

### Сценарий
1. Открыть раздел управления как owner/admin.
2. Найти pending смену.
3. Утвердить смену.
4. Отдельно проверить отклонение смены.

### Ожидаемый результат
- Pending смены видны в approve flow.
- Approve переводит смену в утверждённую.
- Reject переводит смену в отклонённую.
- Экран не падает.

## 3. History / Payroll после approve

### Сценарий
1. Утвердить смену.
2. Открыть History.
3. Проверить payroll summary за выбранный месяц.

### Ожидаемый результат
- Утверждённая смена видна в истории.
- Payroll summary считает только approved смены.
- Pending и rejected не входят в выплату.

## 4. Модели оплаты

### Hourly
1. Создать сотрудника с почасовой моделью.
2. Создать и утвердить смену.

### Ожидаемый результат
- Выплата считается по часам.

### Fixed shift
1. Создать сотрудника с моделью `Фикс за смену`.
2. Создать и утвердить смену.

### Ожидаемый результат
- Выплата фиксированная за смену.
- Часы не ломают расчёт выплаты.

## 5. Фильтр по точкам

### Сценарий
1. Открыть History как owner/admin.
2. Выбрать конкретную точку.
3. Сменить фильтр на "Все точки".

### Ожидаемый результат
- Список смен фильтруется по venue.
- Payroll summary и export используют тот же scope.
- Если venue пустой, смена не ломает экран.

## 6. Export

### Сценарий
1. Попробовать экспорт выплат в XLSX.

### Ожидаемый результат
- Экспорт скачивается как файл.
- Если export сломан, это отмечается как known issue и проверяется отдельно.

## 7. Права обычного сотрудника

### Сценарий
1. Открыть приложение как обычный сотрудник.
2. Проверить доступные разделы.

### Ожидаемый результат
- Нет доступа к управлению командой.
- Нет доступа к админским действиям.
- Видны только свои данные.

## 8. Доступ owner/admin

### Сценарий
1. Открыть приложение как owner/admin.
2. Проверить управление, approve flow, history и payroll.

### Ожидаемый результат
- Owner/admin видит команду, точки, approve flow, историю и payroll.

## 9. Архив сотрудников

### Сценарий
1. Открыть управление командой.
2. Проверить активных и архивных сотрудников.
3. Деактивировать и восстановить сотрудника.

### Ожидаемый результат
- Активные и архивные сотрудники разделены.
- Архив сохраняет историю и выплаты.
- Физическое удаление не требуется.

## 10. Темы light / dark

### Сценарий
1. Переключить light theme.
2. Переключить dark theme.

### Ожидаемый результат
- Текст читаем в обеих темах.
- Карточки, inputs и навигация не сливаются с фоном.

## 11. Telegram avatar fallback

### Сценарий
1. Открыть профиль.
2. Проверить наличие avatar.
3. Проверить fallback, если фото нет.

### Ожидаемый результат
- Показывается Telegram avatar, если он доступен.
- Если фото нет, отображаются инициалы или аккуратный fallback.

## 12. Empty states

### Сценарий
1. Открыть разделы без данных.

### Ожидаемый результат
- Пустые состояния читаемые и спокойные.
- Нет blank screen.

## P0 Regression Checklist

- Создание смены работает.
- Approve / Reject работают.
- Payroll считает только approved.
- Fixed shift не ломает расчёт.
- Фильтр по точкам не ломает History / Payroll.
- Export не падает и даёт файл.
- Права обычного сотрудника сохраняются.
- Owner/admin доступ не ломается.
- Архив сотрудников работает без удаления данных.
- Light / dark theme остаются читаемыми.
- Telegram avatar fallback не падает.
- Empty states не роняют UI.
