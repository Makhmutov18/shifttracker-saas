# Web Admin Gaps

Документ фиксирует ограничения актуального backend. Web-admin не имитирует отсутствующие возможности и не хранит рабочие данные локально.

## Auth

- Самостоятельный web-login отсутствует. Production-доступ возможен только внутри Telegram.
- Безопасный будущий flow описан в `WEB_ADMIN_AUTH_PLAN.md`.

## Смены

- `GET /api/shifts` поддерживает месяц, год и точку, но не произвольный диапазон дат, employee/status query и серверную пагинацию. Дополнительные фильтры применяются к уже полученному месяцу.
- Shift DTO не возвращает вложенные данные сотрудника и точки. Web-admin сопоставляет их с `/api/admin/users` и `/api/admin/venues`; при отсутствии доступа показывает безопасные fallback.
- Массовое утверждение не реализовано.

## Команда

- Создание пользователя возвращает Telegram invite link; отдельного web onboarding нет.
- Нет server-side поиска и пагинации сотрудников.
- Восстановление архива выполняется существующим `PATCH is_active=true`.

## Точки

- Venue содержит только `id`, `name`, `is_active`. Адрес и описание недоступны и показаны как неподдерживаемые поля.
- Backend не возвращает количество сотрудников в Venue DTO; оно считается как количество уже загруженных users, без финансовых вычислений.
- Нет server-side пагинации точек.

## История действий

- `/api/audit-logs` поддерживает только страницу и limit. Фильтр периода и типа события выполняется по загруженной странице.
- Endpoint ограничивает общий журнал текущей точкой пользователя; owner не может выбрать общий audit всех точек через query.
- Raw JSON намеренно не показан как основной контент.

## Обзор

- Нет отдельного агрегированного endpoint. Экран использует несколько существующих запросов.
- Нет исторической аналитики и графиков; web-admin их не выдумывает.
- Сводка по точкам ограничена доступными shifts/users/venues текущего периода.

## До production-запуска

- реализовать безопасный самостоятельный web-login;
- решить CORS и deployment topology для отдельного frontend origin;
- добавить backend pagination/filter endpoints для shifts, users и audit;
- добавить address/description в Venue только отдельной schema/migration задачей;
- добавить integration/e2e tests web-admin с реальной Telegram auth-сессией;
- проверить роли senior/delegated manager и venue scope на production-like данных;
- провести desktop/tablet accessibility и security QA.
